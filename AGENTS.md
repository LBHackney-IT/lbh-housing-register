# Agent notes

When the user supplies raw **Sentry** JSON (preferred), a Sentry issue URL/id, event, stack trace, exception, or breadcrumbs and wants a fix or pull request, follow [docs/agent/sentry-issue-to-pr.md](docs/agent/sentry-issue-to-pr.md). Never connect to or access Sentry with authenticated tooling, API credentials, or browser sessions. Redact pasted evidence before analysis; do not save raw JSON in the repository or PR. If a URL or partial paste lacks enough evidence, ask for the specific missing JSON, frames, exception, or breadcrumbs.

At the start, run `node scripts/agent/github-preflight.mjs`. A warning about GitHub CLI, authentication, or `origin` is informational: tell the user once, continue all local work, and leave unavailable push/PR steps for the user. Draft PRs must target **`development`**. Triage by _what produced the event_ (our runtime vs SDK ingest vs neither), not by matching a previous Sentry incident. After triage, check open PRs into `development` for file or issue overlap: stop if the same failure is already patched; note related PRs; never rebase onto unmerged work unless the human says to. After Sonar/CI returns, ingest findings on the PR’s own diff only. Use the PR body in [.github/PULL_REQUEST_TEMPLATE/sentry.md](.github/PULL_REQUEST_TEMPLATE/sentry.md).

**Guards (Cursor only):** [`.cursor/hooks.json`](.cursor/hooks.json) runs `scripts/agent/deny-dangerous-shell.mjs` on `beforeShellExecution` and `scripts/agent/secret-path-gate.mjs` on `beforeReadFile`. These do not run in Husky — normal commits and pushes are unchanged. Other agents follow the same rules from the playbook.

**New code coverage:** added production source, and added lines in modified production source, must have at least **80%** Jest coverage (statements and branches). Do not commit a PR-ready change until `npm test` and `node scripts/agent/new-code-coverage.mjs` both pass. Specs, Cypress, docs, and `testUtils` are excluded from the gate.
